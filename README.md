# 扫描书转 Markdown（OCR → 图 / 标题 / 正文三分）

把扫描版书籍的页面图片（PNG）自动转换为结构化 Markdown：输出**正文段落**、**章节/小节标题**（`##` / `###`）、**插图与表格**（自动裁图引用）三类元素。纯本地运行，无大模型、无云端依赖，**确定性输出**（同一输入必然得到字节级一致的产物）。

```
输入: 687 张扫描页 p3.png ... p692.png
输出: 20 章 Markdown + 116 张裁图 + 每页结构化 blocks JSON
```

> 章节边界（前言/编/章/参考文献的页范围）**自动从 OCR 标题检测**：扫描每页 blocks 中的标题行（"第X章" / "第X编" / "参考文献"），相邻标题页之间构成一段。不再需要手写页范围表（本书自动检测出 5 编 + 13 章 + 前言 + 参考文献）。

---

## 为什么 Python + Swift 混合？

这是**技术选型的自然结果，不是刻意为之**：

| 阶段                         | 语言                      | 原因                                                                                                                                                                                                                                  |
| ---------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OCR（文字识别）              | **Swift**（macOS Vision） | `VNRecognizeTextRequest` 是苹果原生 API，**只能从 Swift 调用**；且它是本地中文 OCR 中识别质量最好的（免费、离线，687 页约 13 分钟）。Python 替代方案都不行：Tesseract 中文书排版识别差，PaddleOCR / EasyOCR 依赖重（torch 几个 GB）。 |
| 布局分析（图/标题/正文分类） | **Python**                | OCR 之后全是数据活：图像裁剪（PIL/numpy）、文字像素颜色提取、行聚类、正则、JSON 组装。Python 生态成熟、迭代快（改个阈值重跑全量约 2 分钟）；用 Swift 做这些字符串/像素处理效率极低。                                                  |

**两者如何协作**：Swift 只负责产出每页的 OCR 结果（文本 + 归一化坐标 JSON），写入 `out/ocr/pages/` 与 `out/ocr/pages_json/`；Python 只读取这些文件做后续分析。**中间以 JSON 文件为协议解耦**——OCR 引擎可换（如换成 PaddleOCR），布局分析也可单独替换，互不影响，且每步产物都落盘、便于调试。

## 目录结构

```
ocr-book-to-md/
├── ocr_batch.swift      # ① OCR 引擎（macOS Vision，zh-Hans + en）
├── detect_figs.py      # ② 图/标题/正文三分检测（核心算法）
├── build_md.py         # ③ 组装 Markdown（章节边界自动推导）
├── README.md
├── data/                # 输入：示例书《进化心理学》第 6 版截图（687 张）
│   └── images/      687 张原图 p3.png..p692.png
└── out/              全部产物（中间 + 最终）
    ├── ocr/         ① 的产物：pages/（纯文本）+ pages_json/（坐标 JSON，协议文件）
    ├── blocks/      ② 的产物：每页结构化元素 JSON
    ├── figs/        ② 的产物：116 张插图与表格裁图
    └── md/          ③ 的产物：20 章 Markdown（最终交付）
```

> 注：`data/` 只放输入（截图）；所有产物都进 `out/`。重新跑前先 `rm -rf out`（防旧文件残留）。

## 快速开始（一键）

```bash
# 直接用默认目录（data/images → out/），零参数：
python3 run.py

# 或显式指定输入/输出：
python3 run.py --images data/images --out out

# 复用已有 OCR 结果（跳过 Swift OCR，秒级）：
python3 run.py --force-ocr  # 强制重跑 OCR；默认自动复用 out/ocr 缓存
```

首次运行自动执行三步（OCR → 布局分析 → 组装），OCR 产物落在 `out/ocr/`；重跑自动复用该缓存。输出为**自包含集合**，可直接拷贝/发布：

```
out/
├── md/       20 章 Markdown（正文 + 标题 + 图片引用，最终交付）
├── figs/     116 张插图与表格裁图（被 md 引用）
├── blocks/   每页结构化元素 JSON（中间）
└── ocr/      OCR 产物（中间，可删除；删后重跑自动重新生成）
```

### 分步执行（调试/换书时用）

```bash
# ① OCR：扫描页 → 文本 + 坐标（首次或换书时执行，产物进 out/ocr/）
swift ocr_batch.swift <imgDir> <txtDir> <jsonDir> [startPage] [endPage]
# 例：swift ocr_batch.swift data/images out/ocr/pages out/ocr/pages_json 3 692

# ② 检测：坐标 JSON + 原图 → 图/标题/正文三分
#    路径默认值内化：OCR 坐标 = <out-dir>/ocr/pages_json（自动推导），可零参数裸跑
rm -rf out && python3 detect_figs.py            # 默认 data/images → out/
#   换书：python3 detect_figs.py --img-dir 别的截图目录 --out-dir 别的输出

# ③ 组装：blocks → 章节 Markdown（章节边界自动推导，默认 out/blocks → out/figs → out/md）
python3 build_md.py --out-dir out
# 可选：--chapters chapters.json 人工覆盖自动推导的章节结构
```

## 检测原理（detect_figs.py）

核心思想：**用字号（行高）区分"正文/标题/图内文字"，用颜色区分标题**。

| 算法                     | 说明                                                                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `body_h` 正文估计        | 满宽行（>85% 页宽）行高的中位数，避免表内两列/小字污染                                                                                                                  |
| `para_clusters` 段落聚类 | 高行（≥0.82×body_h）按行距聚类，簇内含满宽行才算正文段；短行（段落末行）跟前面长行同簇                                                                                  |
| 图注分区（Pass A）       | "图X.X" 图注向上扫到上方正文段下沿；"表X.X" 表注**向下**扫到下方正文段上沿（本书表注在表上方）                                                                          |
| 照片扫描（Pass B）       | 逐行低阈值内容扫描 + 内部空白容忍 ≤40px（照片内亮带不断开）+ 两端扩展；**区内不得有正文段行**                                                                           |
| 标题识别                 | 文字像素颜色（饱和度>0.25 → 绿色标题 `##`）+ 字号（黑色大字 `###`）；排除图内招牌字（>2.2×body_h / 周围无白纸）、表内标题、无上下留白的正文行；相邻标题行聚组再整体校验 |
| tight_crop               | 低阈值保内容（浅色图顶不被切），空白 >12px 才裁                                                                                                                         |

**关键阈值**（正文 ≈ 45–50px 时）：

| 参数         | 值                      | 作用                                                 |
| ------------ | ----------------------- | ---------------------------------------------------- |
| 正文行判定   | ≥ 0.82 × body_h         | 卡在"正文行"与"表格小字(0.6–0.8×)"之间，防表格被截半 |
| 标题（彩色） | sat>0.25 且 ≥1.06×      | `##`                                                 |
| 标题（黑色） | ≥1.18× 且 0.14W≤w≤0.92W | `###`                                                |
| 图内巨字排除 | >2.2×                   | 照片招牌等                                           |
| 空白判定     | rowsum > max(3, 0.4%W)  | 内容/空白阈值                                        |

## 确定性说明

- ②③ 是纯确定性代码（无随机、无网络、无 LLM）：实测重跑全量，687 blocks + 116 裁图与既有产物 **md5 字节级一致**。
- ① OCR 在同一台 Mac 同版本 macOS 下结果也确定（实测单页与既有产物逐行一致）；换系统版本可能略有差异。
- 重跑 ② 前**必须清空输出目录**，否则页面图区数变化后旧裁图会残留。

---

## 已知限制

- 无"图X.X"标题、内容稀疏的小图检不出（如 p57 的 2.5 小图），OCR 会泄漏几行坐标数字到文本流。
- 部分"学习目标"编号行（"1.界定策略干扰理论"）字号略大，被误判为 `###`。
- 跨页表格的"（续）"表头在下一页作为文本保留（非错误）。
- 阈值针对正文 45–50px 的书籍调校；换书时若字号差异大，需调整 `detect_figs.py` 顶部的阈值常量。
